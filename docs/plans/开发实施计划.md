# 词光拓展开发实施计划（PLAN）

日期：2026-10-27。状态：执行中；详见 [执行进度](./执行进度.md)。对应 [产品规划 PRD](./学习产品拓展规划.md)。

目标：保留现有雅思学习，交付可切换学员和课程的小学英语、幼儿汉字学习闭环。本文包含未来开发任务，不表示功能已经实现。

当前进度：P2 学习策略核心（T13–T19）、P3 T20–T24 小学英语闭环及 P4 T25–T30 汉字亲子闭环工程已完成；小学今日小课、汉字主题地图、共读、找字和家长面板可体验。教学审校与音频仍待 T04/T33，P4 内容验收不因工程完成而放行。下一项为 P5 T31 内容生成规范与课程清单。

验收范围：P2 完成指学习核心与恢复逻辑通过验证；P4 完成指汉字字卡、共读、找字、家长面板与二维地图通过工程和隔离浏览器验证，20 字人工审校与预录音频仍属 T04/T33。

## 1. 发布范围与工期假设

V1：原雅思兼容 + 本地多学员 + 多课程 + 小学 300 词 + 汉字 100 字 + 儿童练习 + 家长设置 + 备份恢复。

估算条件：一名熟悉项目的开发者全职，英语与幼儿内容审校者可按时配合。工程预计 40–53 人日，内容制作与审校单独计量；含两周家庭试用和返工，日历周期建议预留 11–14 周。没有审校资源时，只交付技术预览，不能按正式内容版验收。

开发依赖：P0 → P1 → P2 → P3 → P4 → P5 → P6。内容生产在 P0 确定样板后可独立推进，发布前汇合。阶段时间仅为估算，必须按验收结果推进。

| 阶段 | 工程估算 | 产出 | 放行条件 |
| --- | --- | --- | --- |
| P0 基线与样板 | 3–4 人日 | 旧行为基线、30 词/20 字样板、模型契约 | 样板可用于设计，兼容边界确定 |
| P1 多课程与迁移 | 8–10 人日 | 课程注册、学员隔离、v3 存储、备份 | 数据迁移和隔离验证通过 |
| P2 学习策略核心 | 5–7 人日 | 分龄会话、题型注册、评分与中断处理 | 首次计分、限量与失败处理正确 |
| P3 小学英语闭环 | 6–8 人日 | 儿童词卡与三种主要练习 | 30 词样板可完整学习复习 |
| P4 汉字亲子闭环 | 7–9 人日 | 汉字卡、找字、配对、共读与家长区 | 20 字样板可完整使用 |
| P5 内容与发布准备 | 6–8 人日 | 300/100 内容包、资源与离线处理 | 内容审校完成、兼容回归通过 |
| P6 试用与修正 | 5–7 人日，分布在两周试用及修正期 | 试用反馈、修复记录、V1 | 阻断项归零、验收记录完整 |

- [x] T08 增加本地昵称档案；设备设置与学员/课程设置分开存储。新档案和新课程偏好使用独立本地键保存；旧 v2 雅思数据保持原样，迁移留待 T09。
- [x] T09 实现 v2 → v3 迁移：读取 → 暂存快照 → 校验 → 写新记录 → 写迁移完成标志；原数据不删除。失败可由同一快照续跑，损坏或冲突的 v3 数据停止而不覆盖。
- [x] T10 实现完整备份、预检与恢复，兼容旧 v2 备份导入默认雅思学员；明确替换范围。恢复前展示档案/课程数量并要求确认，只替换词光本地键，失败尝试还原恢复前快照。
- [x] T11 更新路由携带课程身份；原 `#/w/...` 和 `?w=...` 无课程链接仍按雅思解析，未知课程/条目显示可恢复错误。新课程地址使用 `#/explore?course=...`，可选 `entry=...` 用于受保护的条目定位。
- [x] T12 切换学员/课程时保存当前状态并隔离请求，处理多标签页存储更新。切换学员/课程时主动持久化在途状态、终止并使在途异步请求失效（单调递增 token + ContextIsolationCoordinator），监听 storage 事件在多标签页间同步学员选择、课程设置与学习进度，异常数据静默忽略防止跨标签污染。

验收场景：

1. 旧用户升级后卡片数、due、收藏、历史一致；重复升级不重复生成档案。
2. 写入失败或迁移中断后旧记录仍可读取，不显示假成功。
3. 同一个单词在两个课程、两个学员下互不覆盖。
4. 学员 A 学习中切到 B，A 的延迟图片/词条请求不得污染 B。
5. 导入错误版本、破损 JSON、错误课程和异常会话时给出明确结果，不部分覆盖现有记录。
6. 导出全部档案 → 干净环境导入 → 校验学习数据一致；冲突时按明确选择恢复。

## 10. 测试策略与执行门槛

优先测试用户可见行为及存储边界，复用项目现有 Node test + tsx 测试入口；已有 store/srs/text/typing 测试作为基线。高层测试以“加载课程 → 建立会话 → 提交答案 → 恢复进度”为主，迁移和题型资格做必要的边界测试。

需要新增：

- 迁移幂等、写入失败回退、跨学员/课程隔离、备份往返。
- 首次计分、重试不计分、协助不算独立正确、跳过不记错、会话上限。
- 媒体不足/干扰项不足时题型降级与未缓存内容处理。
- 旧链接、刷新续学、路由切换和异步返回竞态。

浏览器端用现有 Playwright 依赖补充关键流程脚本，不必为每个小组件写同构测试。P0 确定夹具和测试入口；发布前运行 `npm test`、`npm run build`、`npm run check:atlas` 以及新增课程校验和浏览器流程脚本。新增命令在实现时注册，当前并不存在。

每阶段交付记录包含：已完成任务、验收证据、未完成项、数据兼容影响和后续依赖。没有通过发布门槛，不用“已基本完成”替代验收。
